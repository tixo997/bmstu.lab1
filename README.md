## Сборка и запуск

Каждый `.cpp` — самостоятельная программа со своей функцией `main`. Их нужно собирать отдельно. Используется стандарт C++17; достаточно стандартной библиотеки.

### GCC / MinGW

```sh
g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic part1_series.cpp -o part1_series
g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic part2_students.cpp -o part2_students
```

В Windows PowerShell:

```powershell
.\part1_series.exe
.\part2_students.exe
```

Запуск второй программы с готовым вводом в PowerShell:

```powershell
Get-Content examples/students_input.txt | .\part2_students.exe
```

В Linux / macOS:

```sh
./part1_series
./part2_students < examples/students_input.txt
```

### Clang через Zig

Если установлен Zig 0.13.0, вместо `g++` можно использовать `zig c++`:

```sh
zig c++ -std=c++17 -O2 -Wall -Wextra -Wpedantic part1_series.cpp -o part1_series.exe
zig c++ -std=c++17 -O2 -Wall -Wextra -Wpedantic part2_students.cpp -o part2_students.exe
```

## Часть 1. Операторы цикла

### Условие задачи

Сравнить число слагаемых, необходимых для достижения точности ε = 10⁻², 10⁻⁴ и 10⁻⁶ при вычислении числа π по разложению:

$$
\pi = 4\left(1-\frac{1}{3}+\frac{1}{5}-\frac{1}{7}+\ldots\right).
$$

Представить реализации с предусловием (`while`), с постусловием (`do-while`) и с циклом `for`. При вычислении суммы считать точное значение неизвестным. Вывести справочное значение π только после результатов.

На предоставленной фотографии приведено одно разложение. Поэтому здесь сравнивается число слагаемых этого ряда для трёх точностей. Сравнение с другим рядом требует его формулы.

### Решение и критерий остановки

Суммируются слагаемые

$$
a_k = \frac{4(-1)^k}{2k+1},\qquad k=0,1,2,\ldots
$$

Знак меняется на противоположный после каждого шага. Степени и факториалы не вычисляются.

Ряд знакочередующийся, модули слагаемых монотонно убывают к нулю. По оценке остатка ряда Лейбница после N слагаемых:

$$
|\pi-S_N|\leq\frac{4}{2N+1}.
$$

Суммирование заканчивается, когда модуль **первого отброшенного слагаемого** становится не больше ε:

$$
\frac{4}{2N+1}\leq\varepsilon.
$$

Для проверки этого условия значение π не требуется. Программа вычисляет `acos(-1.0)` только после вывода всех результатов, чтобы напечатать справочное значение. Конечная десятичная запись является машинным приближением к точному π.

Оценка даёт **достаточное число слагаемых для гарантии точности в точной арифметике**, а не минимальное число по фактической ошибке относительно заранее известного π. При машинном суммировании дополнительно возникает погрешность округления; для заданных точностей используется `double`.

### Три вида цикла

- `sumWhile`: условие проверяется перед добавлением очередного слагаемого.
- `sumDoWhile`: сначала добавляется слагаемое, затем проверяется условие. Все заданные ε меньше 4, поэтому хотя бы одно слагаемое необходимо.
- `sumFor`: условие остановки, увеличение счётчика и смена знака записаны в заголовке цикла.

Во всех трёх функциях слагаемые складываются в одном порядке и применяется один критерий остановки. Вид цикла не меняет математическую скорость сходимости. Для данного алгоритма естественен `while`: повторения продолжаются до выполнения условия точности. Время работы здесь не измеряется — по условию скорость сходимости оценивается числом слагаемых.

### Результаты и ручная проверка

Из неравенства для остатка:

$$
N\geq\frac{4/\varepsilon-1}{2},\qquad
N_{\min\text{ по оценке}}=\left\lceil\frac{4/\varepsilon-1}{2}\right\rceil.
$$

| ε | Число слагаемых N для каждого цикла | Приближение π | Верхняя оценка остатка |
|---|---:|---:|---:|
| 10⁻² | 200 | 3.136592684839 | 4/401 ≈ 9.97506234·10⁻³ |
| 10⁻⁴ | 20 000 | 3.141542653590 | 4/40001 ≈ 9.99975001·10⁻⁵ |
| 10⁻⁶ | 2 000 000 | 3.141592153590 | 4/4000001 ≈ 9.99999750·10⁻⁷ |

Справочное значение: π ≈ 3.141592653589793. Последние разряды вычисленной суммы могут зависеть от компилятора и представления `double`.

Для каждого N оценка не превышает ε, а для N−1 ещё превышает ε. При уменьшении допустимой ошибки в 100 раз число слагаемых увеличивается в 100 раз. Ряд сходится медленно: для ε = 10⁻⁶ по выбранной оценке требуется два миллиона слагаемых. Все три цикла дают одинаковые результаты.

Полный вывод: [examples/series_output.txt](examples/series_output.txt).

## Часть 2. Массивы и структуры

### Условие задачи

Определить структуру «студент»: ФИО и массив элементов структуры «дисциплина» с результатами сдачи сессии, не менее четырёх дисциплин. Структура «дисциплина» содержит название и оценку.

Число студентов n вводится с клавиатуры. Для строк использовать `string`, для массива структур — `vector`. Ввод и вывод одного студента выполнить отдельными функциями. После ввода вывести все исходные данные для контроля.

Определить, **сколько студентов имеют неудовлетворительную оценку хотя бы по одному предмету**. Выявить недостаток представления результатов сессии одной группы и предложить способы его устранения.

### Представление данных

```cpp
struct Discipline
{
    std::string name;
    int mark;
};

struct Student
{
    std::string fio;
    std::vector<Discipline> disciplines;
};
```

Группа хранится в `std::vector<Student> group(n)`. Число дисциплин определяется через `disciplines.size()`, поэтому отдельное поле с этим числом не требуется.

Принята пятибалльная шкала с допустимыми оценками 2–5; неудовлетворительная оценка — 2. Программа запрашивает положительное число студентов, не менее четырёх дисциплин у каждого, непустые ФИО и названия. Некорректные числа запрашиваются повторно; при преждевременном завершении ввода выводится сообщение об ошибке.

### Алгоритм

1. Ввести n и создать массив студентов.
2. Функцией `inputStudent` ввести ФИО, число дисциплин, их названия и оценки каждого студента.
3. Вывести n и все введённые данные, используя `printStudent` для вывода одного студента.
4. Функцией `countFailed` перебрать студентов и дисциплины каждого.
5. При первой оценке 2 увеличить счётчик студентов и выйти из внутреннего цикла с помощью `break`.

Студент с несколькими двойками учитывается **ровно один раз**. Название предмета для поиска не запрашивается: проверяются все предметы.

### Контрольный пример

| Студент | Mathematics | Physics | Programming | History |
|---|---:|---:|---:|---:|
| Ivanov Ivan Ivanovich | **2** | 4 | 5 | 3 |
| Petrov Petr Petrovich | 5 | 5 | 5 | 5 |
| Sidorova Anna Sergeevna | **2** | **2** | 4 | 4 |

У Иванова одна двойка, у Петрова двоек нет, у Сидоровой две двойки. Ручной подсчёт даёт **2 студента**, хотя неудовлетворительных оценок всего три.

Результат программы после контрольного вывода данных:

```text
Students with at least one unsatisfactory mark (2): 2
```

Ввод: [examples/students_input.txt](examples/students_input.txt). Полный вывод: [examples/students_output.txt](examples/students_output.txt).

### Недостаток представления и способы устранения

Для одной группы список дисциплин обычно общий, но в указанной структуре названия хранятся отдельно у каждого студента. Это дублирует данные, расходует память и допускает расхождения: опечатки, разные названия одного предмета, разный порядок и состав дисциплин.

Возможные решения:

1. Вынести общий список названий дисциплин в структуру группы. У каждого студента хранить массив оценок, где индекс соответствует дисциплине в общем списке. Необходимо проверять соответствие размеров массивов.
2. Создать общий справочник дисциплин с уникальными идентификаторами. У студента хранить пары «идентификатор дисциплины — оценка». Это удобно, если индивидуальные наборы дисциплин различаются.

В программе сохранена структура, прямо требуемая заданием: название и оценка находятся в каждом элементе `Discipline`. Предложенные изменения описаны как способы устранения недостатка.

## Проверка программ

Обе программы собраны и запущены в Windows с помощью `zig c++` (Zig 0.13.0), стандарт C++17, параметры `-O2 -Wall -Wextra -Wpedantic`.

Проверены:

- совпадение всех трёх реализаций ряда для каждой из трёх точностей;
- соответствие числа слагаемых оценке остатка и фактической ошибки заданной точности;
- контрольный пример со студентами: результат 2;
- отсутствие двоек: результат 0;
- двойки по разным предметам и несколько двоек у одного студента;
- пять дисциплин, ФИО с пробелами и кириллицей;
- повторный ввод при неверных числах, пустых строках и недопустимых оценках;
- завершение с сообщением об ошибке при неполном вводе.

Файлы `examples/*_output.txt` получены запуском программ, а не составлены вручную.
